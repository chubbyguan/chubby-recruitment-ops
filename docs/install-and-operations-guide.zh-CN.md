# 社交招聘工作流｜安装与操作指南

版本：0.8.0

适用工具：Codex、Claude Code

## 这套工作流怎么用

把插件安装到自己的 Agent 后，把你的岗位、招聘邮箱、招聘数据表格和发布渠道告诉 Agent。个人招聘者和任意规模的团队都可以使用。

之后日常招聘都可以直接和 Agent 对话，不需要自己运行脚本：

```text
岗位 → Agent 生成招聘内容 → 人工发布 → Agent 收简历 / 同步招聘系统
→ 岗位匹配和初筛 → 分开同步候选人和投递 → IM 推荐
→ 人工确认约面 → Agent 核验日历和纪要 → 人工决定 → 招聘日报
```

Agent 负责整理和执行流程，人负责审核内容、发布帖子，以及决定是否约面、淘汰和录用。

如果历史投递缺少稳定岗位版本，Agent 会只把那条投递放进“岗位版本迁移复核”，
不会让整轮失败。高分但硬门槛还没核实的人会进入“补事实 / 补资料”队列，
不会直接推荐约面。

## Agent 会按三种方式运行

| 方式 | 用途 | 范围 |
| --- | --- | --- |
| `quick` | 你在聊天里处理日常招聘 | 一个岗位内容、一个人、一次面试、一条通知、推荐/日报快照，或最多 5 封新邮件 |
| `scheduled` | 每天的自动任务 | 从上次成功位置继续处理增量数据 |
| `maintenance` | 改插件、跑测试、同步 GitHub | 只动插件仓库，不碰候选人生产数据 |

日常对话默认使用 `quick`，不用再让 Agent 每次跑完整闭环。正式日报由
19 点的 `scheduled` 任务生成。只有你明确说“修改插件、测试或同步 GitHub”
时才使用 `maintenance`。

一轮任务只能使用一种方式。如果既要马上处理候选人，又要修改插件，先完成
`quick` 业务任务，再单独开始 `maintenance`。这样更快，也避免测试和真实
招聘数据互相影响。

## 第一步：安装插件

### 使用 Codex

在终端运行：

```bash
codex plugin marketplace add chubbyguan/chubby-recruitment-ops --ref main
codex plugin add chubby-recruitment-ops@chubby-recruitment
```

安装完成后，新建一个 Codex 任务。

### 使用 Claude Code

在终端运行：

```bash
claude plugin marketplace add chubbyguan/chubby-recruitment-ops
claude plugin install chubby-recruitment-ops@chubby-recruitment --scope user
```

安装完成后，重启 Claude Code。

如果已经用过旧版本，不要删除旧配置。让 Agent 使用 `recruitment-ops-setup` 迁移到 schema 4.0。旧的候选人主表继续保留，但投递、阶段历史和证据要使用独立表，避免一个人投多个岗位时覆盖旧记录。

如果不熟悉终端，可以直接把下面这段话交给当前 Agent：

```text
请帮我安装这个招聘工作流插件：
https://github.com/chubbyguan/chubby-recruitment-ops

请根据我当前使用的是 Codex 还是 Claude Code 执行安装。
安装完成后，告诉我需要新建任务还是重启。
```

## 第二步：准备本工作区信息

第一次配置前，准备好：

| 需要的信息 | 说明 |
| --- | --- |
| 业务工作区 | 本工作区项目在电脑上的文件夹 |
| 招聘邮箱 | 专门用于收简历的邮箱 |
| 招聘岗位 | 当前确定要招聘的岗位和 JD |
| 公司和薪资 | 对外使用的公司名称、已确认的薪资范围 |
| 招聘数据表格 | 现有候选人表格优先 |
| 招聘系统 | 已开通时，让管理员给 Agent 使用的应用开通只读权限 |
| 面试资料 | 日历、视频会议和智能纪要的访问权限 |
| 发布渠道 | 例如小红书、微信群、知乎 |
| 日报接收人 | IM 私聊或招聘群 |

邮箱密码、Token、App Secret 不要写进文档或聊天内容。需要授权时，按 Agent 提示在连接器中完成。

## 第三步：让 Agent 初始化

把下面这段话复制给自己的 Agent，并替换尖括号里的内容：

```text
请使用 recruitment-ops-setup 为我初始化招聘工作流。

业务工作区：<路径>
招聘邮箱：<邮箱>
招聘数据表格：<链接或表格信息>
招聘系统：<已开通 / 未开通>
发布渠道：<小红书、微信群、知乎等>
日报接收人：<IM 私聊或群>

请先检查插件、邮箱和协作工具连接是否正常。
缺少的信息直接问我。
配置完成后，使用虚构岗位、虚构简历和虚构面试做一次测试。
测试通过前不要创建定时任务，也不要发布社交媒体内容。
```

Agent 会依次完成：

1. 检查插件是否安装成功；
2. 确认邮箱当前账号就是招聘邮箱；
3. 读取岗位、招聘数据表、日历、视频会议和智能纪要；
4. 已开通时，读取招聘系统并让你确认岗位映射；
5. 建立本工作区自己的配置；
6. 使用虚构资料跑一次简历和面试测试；
7. 告诉你还缺哪些权限或信息。

第一次测试通过后，再让 Agent 创建日常定时任务。

## 第四步：日常招聘

### 有新岗位时

把岗位 JD 发给 Agent：

```text
请使用 recruitment-ops-run 的 quick/campaign 配置，并调用 social-recruitment-campaign。
只处理岗位 <岗位 ID>。
生成小红书和微信招聘内容。
公司名称、工作地点和薪资只使用我提供的信息。
先给我审核，不要自动发布。
```

Agent 会返回不同渠道的标题、正文、素材建议和投递方式。

### 发布招聘内容

检查内容没有问题后，由账号负责人手动发布。

发布完成后，把链接交给 Agent：

```text
这条招聘内容已经人工发布，请记录发布渠道、时间和链接：
<帖子链接>
```

之后拿到阅读、点赞、收藏、评论或投递数，也可以继续交给 Agent 更新。

### 处理新简历

```text
请使用 recruitment-ops-run 的 quick/inbox 配置。
处理招聘邮箱从上次成功水位开始的下一批新简历，单批最多 5 封。
先核验邮箱账号，再完成重复检查、岗位匹配和数据表同步。
最后告诉我哪些候选人值得人工初筛，哪些人需要补资料。
不要扫描全邮箱、全日历或插件仓库。
```

候选人没有写岗位时，Agent 会在当前招聘岗位中给出匹配建议。

### 同步招聘系统

接入招聘系统后，直接对 Agent 说：

```text
请使用 recruitment-ops-run 同步招聘系统。
先核验招聘系统读取权限和岗位映射，再 dry-run。
检查无错误后，把候选人、投递阶段和面试事实同步到招聘数据表。
不要修改招聘系统里的岗位和候选人，不要自动判定通过或淘汰。
```

第一次需要确认“招聘系统岗位 → 内部岗位 ID”。以后 Agent 会按水位增量
读取；同一条投递或面试重复执行不会重复创建。

### 推荐高分但还没面试的人

```text
请使用 recruitment-ops-run 的 quick/recommendation 配置。
按每个岗位自己的推荐门槛，找出有完整简历、岗位仍在招，但面试表和日历都没有面试记录的人。
把推荐人选、岗位、分数、强证据、最大风险和建议动作通过 IM 发给我。
只创建待我确认的动作，不要自动发面试邀请。
```

Agent 会排除已经面试、已经安排、岗位冻结或证据不完整的人。同一个推荐版本只提醒一次。IM 里可以选择“约面、补资料、人才池、暂不推进”；批准约面后，Agent 再根据日历给出三个可选时间，发邀请仍需人工确认。

每条待复核消息都必须写清楚候选人姓名、岗位、评分拆解、关键证据、
风险、缺失资料、面试事实和可选动作，并附候选人记录与审批记录链接。
如果只看到分数或动作 ID、看不出是谁，不要做决定，让 Agent 重新生成完整
通知。

### 查看招聘日报

```text
请使用 recruitment-ops-run 的 quick 配置，读取当前已同步数据并生成今天的招聘日报。
告诉我今天发布了什么、收到多少简历、候选人匹配哪些岗位，以及建议我下一步跟进谁。
平台数据没有回填时写“未采集”。
```

19 点的自动日报使用 `scheduled`，会按水位增量处理后发送。临时查看日报
不会重新扫描所有历史数据。

### 面试前

```text
请使用 recruitment-ops-run 的 quick/interview 配置，并调用 recruitment-interview-review。
只为候选人 <候选人或稳定 ID> 做面试准备。
按当前岗位要求，整理已验证证据、待确认风险、必问问题、案例题和 AI 实操题。
```

### 面试后

```text
请使用 recruitment-ops-run 的 quick/interview 配置，并调用 recruitment-interview-review。
只核验候选人 <候选人或稳定 ID> 对应的日历、视频会议和智能纪要。
有可用原始纪要的生成评价，没有纪要的列为待补人工记录。
把事实和待决策项同步到招聘数据表，不要替我做最终决定。
```

Agent 会分别记录：面试是否计划、会议是否真实发生、原始纪要是否可用、AI 建议是否完成、负责人是否已经决定。这些状态不能互相替代。

### 需要更新插件时

```text
请使用 recruitment-ops-run 的 maintenance/release 配置。
只修改、测试和发布插件，不要读取邮箱、修改候选人数据表、发送候选人通知
或推进生产水位。测试通过后再提交并同步 GitHub。
```

## 第五步：人工确认

下面这些事情不能直接交给 Agent 决定：

- 发布、修改或删除社交媒体内容；
- 淘汰候选人；
- 发送面试邀请；
- 确认面试时间；
- 合并疑似重复候选人；
- 确认面试通过或关闭；
- 背调、发 Offer 或录用；
- 修改岗位状态和公开薪资。

Agent 可以给建议，但最后由招聘负责人或 HR 决定。

## 不同工作区如何使用

每个工作区都重新运行一次初始化，并使用自己的：

- 招聘邮箱；
- 岗位和 JD；
- 招聘数据表格；
- 发布渠道；
- 日报接收人；
- 定时任务。

不要复制其他工作区的邮箱配置、候选人信息和运行记录。

## 常见问题

### 安装后找不到插件

- Codex：新建一个任务；
- Claude Code：重启后重新打开。

### 邮箱账号不对

停止处理邮件，让 Agent 重新核验账号。账号不一致时不要继续读取。

### 数据表同步失败

把真实招聘数据表链接重新交给 Agent，让它读取当前表格和字段。不要自己猜 Token 或表格 ID。

招聘系统能读、数据表不能写，或数据表能写、招聘系统不能读，都算未接通。
这是两套权限，需要分别处理。

### 很多人已经面试，但招聘表没更新

让 Agent 使用 `recruitment-interview-review` 对照日历、视频会议和会议纪要。招聘群里的聊天只能作线索，不能作为唯一面试事实。

### 有会议但没有纪要

Agent 会先查会议关联的智能纪要，再按时间和标题搜索会议纪要。仍然找不到、权限不足或只有很短的录制时，必须写“无法判断”，由面试官补人工记录。

### 小红书数据没有自动更新

这是正常的。帖子由人工发布，平台数据也需要人工回填给 Agent。

### Agent 说测试通过了，能直接开定时任务吗

先确认邮箱读取、数据表写入和日报发送都真实成功，再明确告诉 Agent 开启。只完成本地测试还不够。

## 开始使用前确认

- [ ] 插件已经安装；
- [ ] Agent 能识别四个招聘 Skill；
- [ ] 邮箱账号就是本工作区招聘邮箱；
- [ ] 招聘数据表格可以读取和写入；
- [ ] 已开通招聘系统时，bot 可以读取岗位、投递、人才和面试；
- [ ] 每个招聘系统岗位已经绑定正确的内部岗位 ID；
- [ ] 候选人、投递、阶段历史和证据没有共用同一张表；
- [ ] 日历、视频会议和智能纪要可以读取；
- [ ] 使用虚构岗位、虚构简历和虚构面试完成测试；
- [ ] 社交媒体仍然由人发布；
- [ ] 知道 Agent 建议不等于最终招聘决定。

完成以上项目后，就可以开始日常使用。
